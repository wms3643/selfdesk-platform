# 架构说明

## 为什么要有这一层

上游 bytedesk 提供完整的客服业务（会话、排队、工单、知识库、组织权限）和管理后台，但有三类事情它不覆盖：

1. **坐席工作台**只提供了默认界面，想按自己的信息密度和操作习惯重做；
2. **运营数据**分散在 `/api/v1` 的多个查询接口里，没有一处能同时看到会话、AI 用量和费用；
3. **品牌与视觉**是 AntD 默认样式，和多语言项目里的其他前端对不上。

这一层就是补这三件事，并且**不改上游 Java 代码**——只替换静态资源、加一个独立的看板服务、在运行时加一层主题。

## 组件

| 组件 | 位置 | 形态 | 作用 |
|---|---|---|---|
| 客服工作台 | `console/` | 纯静态（HTML/CSS/原生 JS） | 会话列表、搜索、筛选、回复 |
| 运营仪表盘 | `dashboard/` | Python + 标准库 HTTP 服务 | 聚合 `/api/v1`，出趋势、分布、AI 费用 |
| 品牌与主题 | `admin-patch/*.js` | 运行时注入 | AntD 主题覆盖、占位页替换、文案清理 |
| 打包器 | `scripts/patch_jar.py` | Python | 把上面三样写进 fat jar |
| 启停与网关 | `scripts/*.ps1` | PowerShell | 拉起依赖、切换 AI 链路 |

## 请求链路

```
                     ┌─────────────────────────────┐
   访客  ──► /chat/  │  bytedesk (Spring Boot:9003)│  /admin ◄── 管理员
                     │                             │
   坐席  ──► /console│  ├─ 会话状态机 / 排队        │
                     │  ├─ 工单 / 知识库 / 权限     │
                     │  ├─ Spring AI（模型可切换）  │
                     │  └─ 静态资源（本仓库覆盖）    │
                     └──────────┬──────────────────┘
                                │ /api/v1 (Bearer token)
                     ┌──────────▼──────────────────┐
                     │  dashboard (Python:8002)    │
                     │  ├─ 线程/访客/工作组聚合     │
                     │  ├─ AI token 用量（读日志）  │
                     │  └─ 30s 自动刷新            │
                     └─────────────────────────────┘
```

## 静态资源替换的边界

上游是编译好的 umi/AntD 产物，本层只碰三类文件：

| 文件 | 处理方式 |
|---|---|
| `static/console/*` | 整目录覆盖（上游这里只是示例页） |
| `static/admin/index.html` | 只追加一行 `<script>`，改一个 `theme-color` |
| `static/selfdesk-*.js` | 新增文件，由上面那行 script 加载 |

不修改任何 `umi.*.js` / `umi.*.css`，因此升级上游时冲突面很小。

## 数据与状态

- 会话、消息、工单、组织：全在上游数据库（默认 H2，也可切 MySQL/PostgreSQL）
- 仪表盘的 token 用量：增量解析应用日志里的 `Published AI token usage event`
- 仪表盘的登录态：服务端内存缓存 6 小时，仅本机使用

## 与 Python 编排层的关系

不是从属关系。上游 Spring AI 自己就能回答；本层的 `ai-gateway.ps1` 只是把 `base-url` 指过去，
让业务侧的模型调用走另一套编排。关掉网关即回退，互不影响。详见 [SPRING-AI.md](SPRING-AI.md)。
